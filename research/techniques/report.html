Hylo Type-Checker Optimizations

This report covers the techniques that make the type checker faster, why each one is sound, what it speeds up and what it costs. It also covers the fixes needed to make the faster checker correct, and the ideas that were tried and retired.

Branch claude/stoic-bell-b2molq Patches research/impl/0001–0011 Binary eq7-3bbd2b60cb89 November 2026

Summary

Every technique sits behind a runtime flag, HYLO_TC_EXPERIMENTS=a,b,…, so it can be measured and verified on its own. Two configurations are recommended:

FIX (semantic fixes only): occurs,fixsubst,eqsolve,extorder,arrowenv,eqmgu,givencheck,budget
FULL (fixes and speed-ups): FIX + symindex,coesrc,traitindex,memberskip,unify,index,absmodel,absquotient,typevec,reifymemo
  • Same output as the baseline on the corpus. Both configurations produce identical types, name bindings, witnesses and diagnostics on all 216 corpus files (192 compiler tests and 24 workloads).
  • No crashes. On the 520 programs written by two rounds of adversarial reviewers, the baseline crashes on 21 and times out on 43. FULL crashes on none and times out on 1.
  • Faster. Standard-library typing is 3.8× faster, and the stress workloads are 10× to 700× faster. Several programs that ran out of memory now finish in milliseconds.

How soundness was checked

  • Semantic oracle. research/exp/tcx.py semtest dumps every expression type, every name binding (including implicit and witness arguments), every witness table and every diagnostic, and compares the dump against the baseline. Both final configurations are identical on all 216 corpus files.
  • Two adversarial reviews. In each review, reviewer agents tried to break the checker: unsound acceptance, regressions, dependence on declaration order, crashes and slow programs. A judge agent re-ran every claim. Every confirmed finding was fixed, and the 520 programs the reviewers wrote are re-run on every build (round3/soundness/regress-final.md).
  • Per-technique argument. Each technique below states why it cannot change the result. For pure speed-ups the argument is "same output". For fixes it is "rejects only what has no consistent reading".

Speed-ups

sound the output is identical to the baseline; only the work changes. Per-flag numbers are measured with that flag alone.

index

Implicit resolution: which givens to trysound
How
The visible givens of each scope are bucketed by the head constructor of their conclusion. A goal headed by P only tries the givens in bucket P plus the wildcards, in their original order and with their original penalties.
Why sound
When no coercion source is visible, a given with a different head fails at its first match and produces no result or child thread, so skipping it changes nothing. The index falls back to the full scan when an equality or wildcard given is visible, when an equality is assumed, or when a declaration is on the stack.
Speeds up
Resolution with many unrelated givens in scope: stdlib 2.2×, breadth40 81×, div-loop-20 10×.
Costs
One index per scope, built in O(visible givens). It does not apply in scopes with equality givens.

absmodel

Implicit resolution: a "will fail" testsound
How
Givens are read as Horn clauses, and their least model is computed bottom-up with terms truncated at depth 2. A subgoal that unifies with no fact of the model is refuted before any thread is formed for it.
Why sound
The abstract model over-approximates every concrete derivation: truncation is monotone, ⊤ unifies with everything, and dropping premises only adds facts. A refuted goal therefore has no derivation, so the selected result, the penalties and any ambiguity are unchanged. Four bugs found in review were fixed: subsumption with ⊤, cyclic substitutions, file models keyed by imports, and renaming apart.
Speeds up
Failing or divergent resolution, which no longer runs to the depth cap: div-branch 150×, div-loop-20 12×.
Costs
About 1.4k facts on the stdlib, a few ms. A base fact deeper than the truncation depth weakens the model.

absquotient

Extends absmodel to scopes with equalitiessound
How
Before this flag, a single where A == B switched the model off. Now, when every equality in scope is ground, every type in a non-trivial equality class is abstracted as ⊤, so the model stays usable.
Why sound
Two types that are equal in the congruence closure differ only at positions in non-trivial classes, so their abstractions unify. A derivation that uses coercions maps to an abstract derivation that does not need them.
Speeds up
Divergent givens in generic code with equality requirements: div-eq-ovl-b3-1 goes from 45 s (or out of memory) to 4 ms.
Costs
Scopes with equalities build their model from scratch. More opaque types mean fewer refutations.

memberskip

Member lookup through extensionssound
How
An extension is skipped when it declares no member with the looked-up name and its applicability check provably has no effect. That is the case when its extendee is already memoized and either the match fails at the root or every visible given is already typed.
Why sound
It only skips a call when everything that call could force is already memoized. The order in which extendees and givens are first evaluated is therefore exactly the baseline's, and so is every cycle cut. This is the property the retired names flag violated.
Speeds up
Programs with many extensions: members-big 14.7× and stdlib 1.7× alone. applies calls on members-big drop from 4,008,000 to 1000.
Costs
One head-shape cache per extension and one "givens settled" bit per scope.

coesrc

Coercion-derivability pre-checksound
How
A given that can never derive a coercion (its head is neither T ~ U nor a bare variable) is remembered in a set, and later scans skip it.
Why sound
The classification depends only on the given's declared type. A skipped given contributes "no" to an OR, so the answer and the early-exit point are unchanged. Types computed under a cycle cut are never cached.
Speeds up
Structural mismatches with many givens in scope: breadth40 7.5× and stdlib 1.2× alone.
Costs
One set of givens per typer.

traitindex

Member lookup through traitssound
How
Each scope keeps a map from member identifier to the visible traits that declare it. A qualified lookup like T.m visits only those traits.
Why sound
A trait without the identifier contributes an empty, side-effect-free lookup. The per-identifier lists keep the order of traits(visibleFrom:).
Speeds up
Qualified lookups with many traits in scope. On the stdlib it is small (1007 → 947 ms); it mostly removes a copy of the typer's state.
Costs
One copy-on-write map per scope.

symindex

Standard-library setupsound
How
The about 24 compiler-known entities (Bool, Int, Movable, …) are found with one scan of the standard library instead of one scan per entity.
Why sound
Same predicate and same order, so uniqueElement and the preconditions behave identically.
Speeds up
Every compilation, by a fixed amount: stdlib −12%.
Costs
One small dictionary during initialization.

typevec

Type-store storagesound
How
A contiguous array mirrors the hash-consed type set, so type projections no longer go through unspecialized generic code.
Why sound
Types are never removed and are appended in insertion order, so element i is the same tree as before. Identities and hash-consing are untouched.
Speeds up
Everything, as a constant factor: 1.1–1.4×, and stdlib −20%.
Costs
8 bytes per type, and a copy of the array after a solver fork.

unify

Unification constant factorsound
How
Unification compares the two dynamic types first, then casts each operand once, instead of matching a tuple of existentials against 20 patterns.
Why sound
The set of type kinds is closed, so a cast succeeds exactly when the dynamic types are equal, and the same per-kind function runs.
Speeds up
Every unification: about 1.1×. Most of the gain overlaps with typevec.
Costs
None measurable.

reifymemo

Substitutionsound
How
Within one reification call, the result for each subterm is memoized. Substitutions are often DAGs, which the baseline walked as trees.
Why sound
Within one call, reification is a pure function of the subterm's identity.
Speeds up
Bindings that share subterms: occurs-dag-18 goes from 8.8 s to 3.7 ms.
Costs
One dictionary per call that has variables.

Correctness fixes

fix changes results on purpose. Each one removes an unsound acceptance, a crash or an order dependence of the baseline, and leaves the corpus identical. Several are also large speed-ups.

fixsubst

Keep substitutions when a match assumes coercionsfix
Problem
When match assumed equalities between mismatching parts, it dropped the variable bindings it had already made. Later premises could rebind them, so a single unrelated V == W let resolution "prove" D == V.
Fix
Keep the bindings. This requires occurs (without it, new cycles crash) and eqsolve (without it, honest equality chains hit the depth cap).
Effect
The bogus derivations in both reviews are rejected, for example c01-single-eq-call, v03-box, assocneg-*.

eqsolve

Decision procedure for closed equality goalsfixspeed-up
How
A closed equality goal is decided by a congruence closure over the ground equality facts (a signature table with use lists, O(n log n)) instead of a search through symmetry and transitivity. Two refinements:
  • An abstract projection (Self::P).X is merged only with a unique concrete projection class.
  • Projections through premises that are not discharged yet are resolved ahead of time when their resolution is unique.
Proofs are rebuilt from the cheapest path and carry the penalty search would have given them.
Why sound
Without injectivity, congruence closure decides exactly the theory that search explores. Open goals, and quantified or conditional equalities, are left to search. The uniqueness rule for abstract projections keeps v-abs-7 valid and associated-type-inequality rejected.
Speeds up
Equality reasoning, which was the one pattern no earlier flag helped: trans-8 330×, assoceq-8 31×, coerc-cache 600×. It also turns wrong acceptances into fast rejections.
Costs
The graph is rebuilt for each closed equality goal (cheap). A premise projection costs one nested resolution.

eqmgu

Open equality goals ?v ~ Xfixspeed-up
How
A goal ?v ~ X, where ?v does not occur in X, gets one thread: bind ?v := X by reflexivity.
Why sound
That binding is the most general solution. Every other solution binds ?v to a type equal to X, and the remaining goals are transported along proved equalities, so the extra solutions only produced false ambiguity.
Speeds up
Equality premises posed while a type variable is still open: open-wide-4 went from out of memory to 202 ms, open-neg-0 from 24 s to 3 ms.
Costs
One occurs check per open equality goal.

extorder

Order-independent lookup through extensionsfix
Problem
An extension whose extendee is being computed is silently skipped, and results computed meanwhile are memoized. Whether a program is accepted depended on the order of declarations.
Fix
Extensions that do not declare the looked-up name are skipped without evaluation. Extendee computations that close a cycle form a group. When the group completes, every lookup its members made is checked against the members' final extendees, and a group whose member may affect one of those lookups is reported as circular.
Why sound
The verdict uses only final extendees and the whole group, so it does not depend on which member was entered first. Skips that could not have mattered are kept.
Costs
One recorded lookup per lookup inside an extendee computation. It rejects mutual cycles that have a unique reading (see Limitations).

givencheck

Givens skipped while their own type is computedfix
Problem
A given is invisible while its own type is being computed, and nothing re-checks it afterwards. This baseline bug accepted programs with no consistent reading (gz1, ge1, gx1), and the verdict depended on declaration order.
Fix
Record each skipped given with the query it was skipped for. Once its type is known, report it as circular if it could have matched that query. Deliberate hiding is not recorded: where-clause scoping, and a conformance resolving its own refined requirements.
Costs
A scan of the visible givens per resolution, and only during declared-type computations.

occurs and arrowenv

Occurs check in unificationfix
Problem
Binding ?a := Box<?a> created cyclic substitutions, and reification then overflowed the stack. Arrow environments were invisible to the "has variables" property, which hid some of these cycles and also left open goals looking closed.
Fix
Refuse cyclic bindings. The walk covers every type kind, including method bundles and arrow environments, and is linear on DAGs. An occurs failure at the root of a match is now a mismatch; before, it was accepted, so a Void value could stand in for a proof of Box<Void>. Arrows include their environment in their properties.
Costs
A linear check per variable binding.

budget

Runaway searchesfix
How
When a search layer ends with no result and more than 100,000 live threads (HYLO_TC_BUDGET), the resolution is abandoned and reported as "implicit resolution is too complex".
Why sound
Abandoning only makes a goal fail. Because it is reported as an error, it cannot quietly steer overload or extension selection, and the program is rejected.
Costs
A valid program that genuinely needs a larger search is rejected. The baseline ran out of memory on these. The limit is a tunable, not a rule of the language.

Limitations and next steps

  • Return-type overloads stay exponential. ovl-ret-9 takes 8 s and ovl-ret-12 times out, as in the baseline. Fixing this needs a sound overload solver that resolves each overload set where the baseline would and commits only a sole survivor.
  • Mutual extension cycles are rejected. extorder rejects two extensions whose extendees depend on each other even when a unique reading exists (v4_noC). The baseline accepts these only through order-dependent memoization. Accepting them in every order needs a fixpoint with rollback.
  • The budget can reject valid programs. Under FIX alone, a few divergent but valid programs hit the limit and are rejected; FULL accepts them because absmodel refutes the dead branches. A stronger abstract model would make the budget unnecessary.
  • Some equality reasoning still uses search. Open goals that are not a bare variable (Box<?v> ~ C) are searched. Projections through less direct premise forms, such as a coerced witness, are not resolved ahead of time.
