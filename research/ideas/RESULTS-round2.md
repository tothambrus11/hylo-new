## 1. symindex

*merged from:* symindex (algorithms lens), tagswitch part (3) for the remaining pass (optional)

*expected gain:* stdlib typing about -13% (13.7% x 23/24, about 20 ms of 160 ms). It saves the same absolute time in every compilation that types or loads the stdlib, so ovl-8-8 and ovr-3-10 also gain about -13% of the whole run, and breadth80 and members-big gain the same 20 ms.

**Rationale.** Largest single profile share that has an exact fix. Program.initializeStandardLibraryCaches is 13.7% inclusive in allon.txt, 16.7% in the gdb sampling and about 13-14% in ovl-8-8 and ovr-3-10. It makes 24 full scans of stdlib syntax, one per StandardLibraryEntity, and each scan does an `as? any Annotatable` existential cast on every node. Most of the 7% conformance-cache self time comes from these casts. The fix is one pass that builds an inverted index. It is pure code motion with a trivial equivalence argument.

**Spec.**

Flag: `symindex` in TyperExperiments (Sources/FrontEnd/Typer/TyperCounters.swift).
Where: Sources/FrontEnd/Program.swift:2004-2018 initializeStandardLibraryCaches. It is called from Typer.swift:40-42 on every stdlib typing and from Program.swift:2075-2077 when the stdlib is loaded from an archive. Related code: select(from:_:) at 2102-2106, SyntaxFilter .symbol at 2141-2142, symbol(annotating:) at 1458-1462, annotations/annotation at 1651-1662.
Change: under the flag, build `var table: [String: [AnySyntaxIdentity]] = [:]` with one loop over `modules.values[a].syntax`, in the same order that select(from:) uses. For each node n with `let s = symbol(annotating: n)`, append n to table[s]. Then, for each `e in StandardLibraryEntity.allCases`, in the same order as today, set `let b = table[e.rawValue]?.uniqueElement` and keep the existing body: castToDeclaration, the precondition/allowPartialStandardLibrary handling, and the assignment to standardLibraryDeclarations[e]. The old loop stays in the else branch.
Optional micro-step: skip nodes whose SyntaxTag is not a declaration before the `as? any Annotatable` cast. Only do this if every Annotatable conformer is a declaration; check this with grep for `: Annotatable` / `Annotatable,` conformances. Otherwise precompute a per-SyntaxTag bit (`tag.value is any Annotatable.Type`, evaluated once per tag) and test that bit instead of casting.
Soundness: filter preserves order and the predicate is identical, so table[s] equals select(from: a, .symbol(s)) element for element, and uniqueElement gives the same value, including nil when the symbol is missing or duplicated. The function has no other side effects. The precomputed tag bit is exact because conformance of a struct type to a protocol is fixed at compile time.
Test: semtest/dump with only symindex, and with all flags, over the 192 tests, the stdlib and the workloads: they must be byte-identical. Add a debug assertion, run once, that the old and new maps are equal. Benchmark type.stdlib.

## 2. typevec

*merged from:* typevec, internfast, tagswitch parts (1) and (2)

*expected gain:* stdlib typing about -15 to -18%: projection about -10%, interning metadata and casts about -3 to -4%, alias probes and context/head casts about -1.5%. breadth80 about -18 to -22% of the run. members-big about -4 to -5%. ovl and ovr get the stdlib share.

**Rationale.** The type store is the hottest piece of infrastructure. StableSet.subscript.getter is 12.6% inclusive on the stdlib and 13.9% on breadth80. StableDictionary.assignValue is 3.6% on the stdlib and 11.9% on breadth80. TypeStore.demand is 11.4%, and the TupleCache/getTupleTypeMetadata2 traffic is about 3.4%. The disassembly shows the cause: StableCollections is a separate module and is neither inlinable nor specialized, so every projection runs unspecialized generic code. Within TypeStore, the same flag also removes the 4 dynamic casts and the box in demand, the Optional and tuple metadata in TypeTree.equals, and the 2 alias-probe casts per unification step. All of these are local constant-factor changes with the same soundness argument (identical identities), so one flag keeps the matrix small. I checked the claims against the code. `types` is private (TypeStore.swift:22), and its only mutation is insert at :93 through StableSet.insert, i.e. assignValue (StableSet.swift:71-73); nothing calls remove. TypeAlias.properties is `.hasAliases` (TypeAlias.swift:20-22). The alias probes are at TypeStore.swift:998-1002, before the `unify` dispatch.

**Spec.**

Flag: `typevec`, read once into a stored `let fast: Bool` in TypeStore.init. Do not read the global var in hot paths.
File Sources/FrontEnd/Types/TypeStore.swift.
(A) Storage. Add `private var trees: ContiguousArray<AnyTypeTree> = []`, `private var tags: [UInt8] = []` and `private var index: [AnyTypeTree: Int] = [:]`. Keep `types` for the off path. In insert(_:) (:92-98), when fast: look up `index[k]`; if it is present, return `.init(offset: i, properties: t.properties)`; otherwise set i = trees.count, append to trees and tags, and set index[k] = i. Prefer a single probe through the `index[k, default: trees.count]` modify accessor. The tag is the dense index of TypeTag(type(of: t)), from TypeTag.indices or a new static table [ObjectIdentifier: UInt8] built once. underestimatedCount and reserveCapacity forward to trees and index. In subscript(n: AnyTypeIdentity) (:733-746), the default branch returns `fast ? trees[n.offset].wrapped : types[n.offset].wrapped`.
(B) Tag fast paths. Add `func tagIndex(_ n: AnyTypeIdentity) -> UInt8?`, which returns nil for the predefined identities (.error, .void, .never) and for variables, and tags[n.offset] otherwise. Use it in tag(of:) (:106-109), cast/castUnchecked (:477-489; a mismatching tag returns nil without projecting), isParameter/hasContext (:111-127), and head, contextAndHead and open (:177-232): if the tag is neither UniversalType nor Implication, return directly, as the `default:` arm does.
(C) Interning, ex-internfast. In demand<T: TypeTree>(_:) (:71-73), branch on `T.self == ErrorType.self`, `Tuple.self`, `UniversalType.self` and `TypeVariable.self`; these comparisons fold at specialization. Use `as!` only inside the matching branch, keep the same `where` conditions (u == .empty, isNever(u)), and otherwise call a generic `insert<U: TypeTree>(_ t: U)` so that the value is boxed once, into AnyTypeTree. In demand(any:) (:76-89), compare `type(of: t)` with those metatypes instead of running the `switch` of `is`/`as` casts. In Sources/FrontEnd/Types/TypeTree.swift:28-30, implement equals(_:) as `guard type(of: other) == Self.self, let o = other as? Self else { return false }; return self == o` under the flag. Put the flag in a `static let` that equals reads.
(D) Alias probes, ex-tagswitch(1). In unifiable at TypeStore.swift:998-1002, guard each probe as `else if (!fast || a[.hasAliases]), let t = self[a] as? TypeAlias` and likewise for b. dealiased (:830-844) already uses the same guard.

Every AnyTypeIdentity, offsets included, is therefore bit-identical to the baseline, and so is everything downstream. (B) tags[i] is written once from the dynamic type of the stored tree. All type trees are structs, so a tag comparison is equivalent to a successful `as?`. (C) There are no subclasses, so `x is S` holds iff type(of: x) == S.self. When the dynamic types differ, `other as? Self` is nil and the old `self == nil` is false, the same as the early return. (D) Every TypeAlias identity carries .hasAliases, because the identity stores t.properties. Predefined identities and variables are never aliases, so a probe skipped when the bit is clear would have failed.

## 3. givenfacts

*merged from:* givenfacts, coesrc (planned), dtree part (a) coercion-source list

*expected gain:* stdlib about -8 to -11%: canDeriveCoercion from 9.6% to under 1%, and the canDeriveCoercions loop plus givens(visibleFrom:) from about 3% to under 1%. breadth80 about -5% (canDeriveCoercions 6.5% there; with no source the scan becomes O(1) once all givens are settled). members-big, ovl and ovr get the stdlib share.

**Rationale.** canDeriveCoercions is 12.6% inclusive on the stdlib (allon.txt) and canDeriveCoercion(_:applying:) 9.6%. 8% of it runs under anonymousImplementation, where the stack is non-empty and both the index and the memo writes are disabled (Typer.swift:4268-4285 and 4303-4305). The exact counts show 58,400 canDeriveCoercion calls, 37,488 misses and only 10,170 distinct keys. The stdlib declares no coercion source at all: every given in StandardLibrary is a conformance (`T is P` or `<..> => X is P`). So the scan almost always concludes 'false' after calling declaredType and contextAndHead on every visible given. A given whose declared type is settled has a fixed classification. That makes it possible to skip non-sources in O(1), to write the per-(given, pair) memo under any stack, and to answer 'no sources visible' without a scan. It is exact and needs no index. This is the lazy, stack-safe form of dtree part (a) and of coesrc.

**Spec.**

Flag: `givenfacts`.
Files: Sources/FrontEnd/Typer/Typer.swift. canDeriveCoercions 4246-4290; canDeriveCoercion(_:applying:) 4298-4337; declaredType(of: Given) 1650-1699; expression(referringTo:) 4180-4194; givens(visibleFrom:) 4130-4154; notOnStack 5272-5281; Memos 52-150.
Data: `struct GivenFacts { kind: Kind; context: ContextClause; head: AnyTypeIdentity }` with `enum Kind { case none, wildcard, equality(EqualityWitness.ID) }`. Add Memos fields `givenFacts: [Given: GivenFacts]`, `scopeToSources: [ScopeIdentity: [Given]]` (set only once every given visible from the scope is settled) and, optionally, `givenWitness: [Given: WitnessExpression]`.
settled(g): `.user(d)` is settled iff d's type is already memoized in the program (the same store setType writes; use the read-only accessor, e.g. program[d.module].type(assignedTo: d) != nil, and NEVER call declaredType to find out). `.nested(_, h)` is settled iff h is settled. The built-in, coercion and recursive cases are always settled. `.assumed` is settled; its type is carried in the environment.
facts(g): return the cached value, or nil if !settled(g). Otherwise compute declaredType(of: g); this has no side effect because g is settled, and for .nested contextOfSelf is memoized and introduce/demand hash-cons to existing ids. Then classify exactly as 4310-4330 does: `u.context.parameters.contains(u.head)` gives wildcard; `cast(u.head, to: EqualityWitness.self)` gives equality; anything else gives none. Store and return.
canDeriveCoercion under the flag: after the existing memo read (4301), `if let f = facts(g)`, switch on f.kind. For .none the result is 0b00. For .wildcard it is 0b11. For .equality, run the existing open/unifiable code with f.context.parameters and the lhs/rhs of the witness. In all three cases write the memo whenever `p.isClosed`, whatever the stack. Otherwise take the old path unchanged, and afterwards call `_ = facts(g)` if g is now settled.
canDeriveCoercions under the flag, after the existing memo read: compute `s = sourcesIfSettled(scopeOfUse)`. This is cached in scopeToSources. Compute it only when every given of the unfiltered visible list is settled: enumerate the groups exactly as givens(visibleFrom:) does but without notOnStack, and keep the givens with kind != none, in order. If s is non-nil, iterate `chain(environment.givens, s.filter(notOnStack))` with the same accumulator, early exit and memo writes as today. If s is empty, environment.givens is empty and p is closed, the result is false and may be memoized even when an implicit is on the stack, because with no source at all the filtered list has none either. If s is nil (something unsettled), run the old loop, which already benefits from the O(1) per-given path.
Optional part (b): expression(referringTo:) returns a cached WitnessExpression for settled givens (4,104 calls for 89 distinct givens).
Counters: givenfacts.fast, givenfacts.unsettled, givenfacts.sourceListHits.
Soundness: (1) Once g is settled, declaredType(g) returns a fixed id: setType is write-once and the other parts are memoized or hash-consed. canDeriveCoercion(p, g) is therefore a pure function of (p, that id), except that the equality branch's open() allocates fresh variables, which only perturbs numbering (index and solver already do this). (2) Skipping the computation for a settled non-source returns the same 0b00, and the declaredType call it omits would have been a no-op. (3) The baseline reads the per-given memo at 4301 under any stack, so writing a value under a stack stores exactly what any later computation would produce. (4) A source list built only when all visible givens are settled, filtered by notOnStack at query time, visits the same sources in the same order as the old loop. The non-sources it omits contribute 0 and have no side effects, and an early exit can only occur at a source. (5) Unsettled givens always go through the baseline code, so the order of first-time declaredType evaluations, and with it cycle-cut behaviour, is unchanged.
Test: semtest identical (alone and with all flags) on the corpus, the stdlib, the workloads, and review/names/*.hylo and review/loopcheck/*.hylo (cyclic programs that exercise unsettled givens). Also check counters: givenfacts.fast should be close to the former miss count (about 37k).

## 5. solver1

*merged from:* solver1, solver (replaces it)

*expected gain:* stdlib about -3 to -6% relative to `solver` on, and about 0% relative to the baseline. ovl-8-8 and ovr-3-10 unchanged (about 4 orders of magnitude better than the baseline). Other workloads unchanged. It also removes a known divergence.

**Rationale.** The counters show that `solver` is pure overhead on the stdlib: 338 probes, 0 pruned, 0 commits, goalSteps +12%, refreshScans 63 -> 3052, and all-minus-solver was faster in 3/3 timing rounds. Its only known divergence, positive/overload-priority.hylo, comes from a commit in a system with a single overload. Deferring only when two or more overload sets are pending makes such systems run baseline code verbatim, which removes both the overhead and the divergence. The ovl/ovr wins (8 and 10 simultaneous sets) are kept. Verified in Solver.swift:102 (`let deferring = TyperExperiments.solver`), 104-118 (loop-top handling), 147-151 (unconditional park), 166 (refresh gated by !deferring) and 594-630 (resolveParked/commit).

**Spec.**

Flag: `solver1`, independent of `solver`. If both are on, solver1 wins; document this.
Solver.swift, in solution(betterThanOrEqualTo:using:):
- Replace the constant `deferring` with a computed test `func deferringNow() -> Bool { (TyperExperiments.solver && !TyperExperiments.solver1) || (TyperExperiments.solver1 && (!parked.isEmpty || probing)) }`. Hoist the two flags into lets.
- Loop top (:104-118): `if !deferringNow() { break }`. The rest is as today: probing stops with probeFinished, then resolveParked, then refresh.
- Overload arm (:147-151): `if TyperExperiments.solver1 { if !parked.isEmpty || fresh.contains(where: { me.goals[$0] is OverloadConstraint }) { me.parked.append(g); return .running }; return me.solve(overload: g).map(SolverStatus.terminated(_:)) ?? .canceled }`.
- Line 166: `if fresh.isEmpty && !deferringNow() { refreshCoercionAndWideningConstraints() }`.
- resolveParked (:594-630): under solver1, if parked.count == 1, remove it and `return solve(overload: g, among: k.candidates)...` directly: no probe, no commit (baseline forking).
Counters: solver1.parkedSystems, plus the existing probes/commits.
Soundness: consider a system in which no two overload constraints are ever pending at the same time (pending meaning in fresh or parked when one is popped). There parked stays empty and probing is false, so deferringNow() is false at every check, and the loop executes exactly the baseline statements: an immediate solve(overload:), refresh at 166, and break at the loop top. Forks inherit the same rule. Systems with two or more simultaneous sets behave like `solver`, apart from the last set being forked rather than probed, which is the baseline action for it. solver1 therefore strictly shrinks the divergence surface of `solver`. It does not prove the multi-set case: the pending solver review and the representation issue of the commit path (X vs A<Void>) remain, and the commit should record its choice exactly as solve(overload:) does.

## 7. memberskip

*merged from:* memberindex (algorithms lens), names (sound replacement), review names-1 fix

*expected gain:* If (c) holds most of the time: on the stdlib, most of names' saving (names removes about 10k matches and the slow applies paths; estimate -10 to -20% of typing, against all-minus-names). members-big: Part E alone gives about -30 to -40% (the cheap test replaces applies, but the scan stays O(#ext)); with E2, about -55 to -65%. Part T: stdlib -1 to -2% beyond nocopy. Measure memberskip.skipped/names.skippedExtensions first: if early-typing unsettledness blocks most skips on the stdlib, the gain shrinks accordingly.

**Rationale.** On the stdlib, `names` removes the most work of any flag (with all others on: matches 14079 -> 3541, applies calls 7216 -> 32). memberindex's extension side would make members-big 2.5x faster. Both are UNSOUND as specified. The review's names-1 shows that skipping applies(e, q) also skips its side effects: the first-time evaluation of extendeeType(e) and, in the slow path, summon over the visible givens, which forces declaredType of givens. memberindex inherits this, because its soundness argument says 'justified by the argument accepted for names'. A sound rule: skip a non-declaring extension only when its applies call provably has no observable side effect. That holds when (i) e's extendee type is already memoized, (ii) the rigid nominal heads of e's extendee and q differ, so the match fails at the head, and (iii) the scope applies runs in has no coercion source and all its givens are settled, so the canDeriveCoercions call after the failed head unification returns false without forcing anything. The stdlib declares no coercion source, so (iii) usually holds once its givens are typed. The trait-side index of memberindex is exact as proposed: lookup(name, lexicallyIn: trait) is syntactic, and the baseline skips empty results at 4826.

**Spec.**

Flag: `memberskip`. Independent of `names`: when it is on, it decides; `names` keeps its own behaviour only when memberskip is off.
Part T (exact, trait side). Add a Memos cache `scopeToTraitsByName: [ScopeIdentity: [String: [TraitDeclaration.ID]]]`, built from traits(visibleFrom:) (Typer.swift:5035-5061) in order, keyed by each identifier of declarations(lexicallyIn: trait). In lookup(_:memberOfTraitVisibleFrom:) (4820-4831), iterate only `byName[name.identifier] ?? []` and keep the existing body: lookup + refineLookupResults + the resolvableWithQualification filter, without the partial application (see nocopy).
Part E (extensions). In resolve(_:declaredIn:applyingTo:in:statically:) (4675-4708), after the declarationsOnStack check, and when e does not declare n.identifier (`declarations(lexicallyIn: .init(node: e))[n.identifier] == nil`), skip e iff ALL of the following hold:

 (b) H(e) and H(q) are both defined and differ. H(x) is the declaration identity of the rigid nominal head of x: take contextAndHead(x).head, dealias it, and if it is a TypeApplication take its abstraction. A struct, enum, trait or other nominal declaration type, or a MachineType, is rigid. A generic parameter, variable, associated/remote type, tuple, arrow, metatype, alias or anything else gives undefined. Cache H(e) per extension.

Otherwise call applies as today. Counter memberskip.skipped (compare it with names.skippedExtensions on the same runs) and memberskip.kept.
Part E2 (index, optional second step under the same flag, once E is gated). Per scope, keep the visible-extension list annotated with positions, plus byName[identifier], byHead[H(e)] and a residual list R of extensions with undefined H(e) or an unsettled extendee. Prune R lazily as extendees settle. When coercionFree(s') holds and H(q) is defined, iterate the position-ordered merge of byName[n.identifier], byHead[H(q)] and R, and apply the same per-e test. Otherwise run the plain loop.
Soundness obligation, which the engineer must check in the code before gating: when (a)-(c) hold, applies(e, q, scopeOfUse) evaluates as follows. givens(lexicallyIn:) is syntactic. extendeeType(e) returns the memo. The t == u fast path fails because the heads differ. The cache read has no effect. In the slow path, formThread(matching: w, to: head(q), in: .empty) runs match. Unifying the opened extendee head with head(q) fails at the rigid head, with or without `unify` (TypeStore.swift:1040-1041, unifiableSameShape). The coercion handler records the pair, match calls canDeriveCoercions over the visible givens of s' with an empty environment, and that returns false with no first-time evaluation, because everything is settled and there is no source. The thread dies with .next([]) (Typer.swift ~3776-3781), and takeSummonResults returns nil. So the only effects are memo writes of values that any later computation reproduces, plus fresh-variable and type-store numbering, which the oracle normalizes and which names/index already perturb. Read formThread/match/takeSummonResults line by line to confirm that no other path is taken: for instance the `coerced` slow path, or alias handling on the q side, which must be dealiased before H. Then the skipped call is unobservable, which refutes the names-1 mechanism: n04 is no longer skipped because E2's extendee is unsettled, and n11/n12 are not skipped because the given is unsettled.

All must be identical to the baseline, including the cases where names diverges. Counters: memberskip.skipped on the stdlib and members-big compared with names.skippedExtensions.

## 8. membermemo

*merged from:* membermemo (strict mode only), cyclecut taint counter as infrastructure (non-semantic use)

*expected gain:* stdlib about -5 to -8% of typing on its own (strict mode); about -3 to -5% on top of nocopy, givenfacts and memberskip. members-big: half of its 2000 lookups repeat (about 1100 distinct), so about -20% without memberskip and -2% with it. breadth80, ovl and ovr only through the stdlib.

**Rationale.** resolve(memberOf:) is 30% inclusive on the stdlib. gdb shows that 1804 type-qualified calls have only 236-254 distinct (name, q, static/file) keys, so 86% are repeats. The fresh part of each call (nativeMemberOf, the trait scan, qualificationForSelection/reify/typeOfImplementation, fresh) is about 15% of the run. The relaxed mode's soundness argument (memo reads and writes under a non-empty stack) is subtle. Strict mode is simpler: write and read only with an empty declaration stack, write only if no stack-dependent decision or cycle cut occurred during the call, and store no variable-bearing candidate. It keeps a large part of the gain at moderate risk. Ranked last because it is the riskiest member of the slate and its gain shrinks once nocopy, givenfacts and memberskip land.

**Spec.**

Flag: `membermemo`.
Infrastructure: `var stackObservations = 0` in Typer. Increment it (1) in the 4 cycle branches (Typer.swift 1314-1318 Binding, 1353-1357 Conformance, 1558-1562 TypeAlias, 1765-1769 extendeeType), (2) when notOnStack returns false (5272-5281; count at its callers 3979, 4135/4142/4149 if it must stay non-mutating), (3) when the declarationsOnStack check at 4680 excludes an extension, and (4) at any other place where membership in declarationsOnStack changes a computed value rather than only a memo write. Grep `declarationsOnStack` and list every use in the PR.
Key: `struct MemberKey: Hashable { n: Name; q: AnyTypeIdentity; scope: ScopeIdentity }`, where scope = lookupScope(scopeOfUse). lookupScope is memoized: the nearest ancestor-or-self s with givens(lexicallyIn: s) non-empty, or a local ExtensionDeclaration or TraitDeclaration lexically in s, or else the file scope. Before using it, audit every use of scopeOfUse in the call tree of resolve(_:memberOf:visibleFrom:) (4590-4609): nativeMemberOf 4635-4657, memberInExtensionOf 4665-4671, declaredIn 4675-4708, applies 4944-4973 (normalized by givens), inheritedMemberOf 4715-4745 (summon, normalized by givens), traits/extensions(visibleFrom:) 4903-4939 and 5035-5061. Confirm that each depends on scopeOfUse only through the things lookupScope preserves. If anything else depends on it (accessibility, for instance), add it to the key or use the raw file + lookupScope pair.
In resolve(_:memberOf:visibleFrom:): Namespace qualifications go to a separate `builtinMemo[Name]` for `.builtin`, if resolve(builtin:) is verified pure. When the flag is on, `!q[.hasVariable]` and `declarationsOnStack.isEmpty`: on a hit, return the entry. On a miss, record `let c0 = stackObservations`, compute as today, and store only if `stackObservations == c0` and no candidate.type has .hasVariable.
Counters: membermemo.hit, miss, tainted, varResult.
Verify mode: HYLO_TC_MEMBERMEMO_VERIFY=1 recomputes on every hit and asserts that the candidates are equal (reference and type). Use it for the gate runs.
Soundness (strict): the writer runs with an empty stack. Every sub-result it used was (i) read from a write-once memo or program table, (ii) computed and memoized during the call, or (iii) computed without memoizing. With no stack observation during the call, nothing in (ii) or (iii) depended on stack contents, and no cycle cut fed a transient .error into the result. A baseline recomputation at a later empty-stack reader is deterministic. It reads the same write-once values that the writer read or wrote, so it produces the same candidates. The skipped recomputation has no observable effect: its sub-results are memoized or recomputed identically, and resolve(memberOf:) reports no diagnostics itself, since diagnostics from first-time typing happen in the writer exactly as in the baseline. The other flags (index, absmodel, givenfacts) take the same path at an empty stack, so the memo replays the configured pipeline, which keeps it independent of other flags. Remaining residual: fresh-variable numbering.
Test: semtest with membermemo alone and with all flags, run in verify mode, on the corpus, the stdlib, the workloads and review/names/*.hylo. Measure membermemo.hit on the stdlib; about 800-1000 hits are expected, given that about 8.2% of memberOf calls come from declaredType with a non-empty stack.

## Rejected

- **internfast**: Not rejected on merit. Merged into typevec part (C): same file, same identity-preserving soundness argument, constant-factor only, so a separate flag would only enlarge the factorial matrix.
- **tagswitch**: Parts (1) (alias probes in unifiable, TypeStore.swift:998-1002) and (2) (tag-first head/contextAndHead/open/cast) are merged into typevec, where they cost nothing with the tags array. Part (3), the SyntaxTag protocol bitmask, is deferred: once symindex removes 23 of the 24 annotation passes, the remaining gain is about 0.5%. symindex's optional micro-step covers the one hot use.
- **flaglet**: Not an optimization flag, so it cannot sit behind a TyperExperiments switch. Recommended anyway as infrastructure in PR #7 (tc/infra), landing BEFORE the next measurement round: snapshot TyperExperiments and TyperCounters.enabled into `static let`s. It removes about 2.5% exclusivity overhead on members-big that biases names/memberskip comparisons. It is exact if nothing writes the flags after startup; grep confirmed that no `TyperExperiments.x =` assignment exists in Sources.
- **memberindex (as specified)**: Its extension-side soundness argument relies on names' 'applies only fills a cache', which the review disproved (names-1: n04, n11, n12, t03). Replaced by memberskip, which keeps the trait index verbatim and adds side-effect conditions for skipping extensions.
- **lookupmemo**: Sound and cheap, but the gain is only 1.5-2.5% on the stdlib and under 1% on the current workloads, since all are single-file. Next round, together with a multi-file workload that shows the O(#files) cost.
- **cyclecut**: SEMANTIC CHANGE (a fix of order-dependent baseline memoization, names-2). Valuable as a separate correctness track, but not in this speed slate. memberskip makes names unnecessary without changing semantics, and membermemo uses only the non-semantic taint counter (the same bump sites). Revisit once the slate is merged, as the one semantic-change PR, with deduplication of the cycle diagnostic.
- **loopsafe**: Gives no speedup on any workload (loopcheck.pruned is 0 when absmodel is on). Its value is soundness, and the simpler action is to drop `loopcheck` from the recommended set: it is redundant with absmodel on every workload and unsound on lc04-07 and lc12. Consider loopsafe later only if the termination niche (lc08-style generic self-loops) matters. Its proof sketch, which equates pending-givens counts with identical stacks, also needs a review first.
- **dtree**: Deferred. givenfacts covers part (a), the coercion sources, which is most of its stdlib gain (canDeriveCoercions), at lower risk and effort. The remaining parts, a stack-independent index with group-offset recomputation and a second-level Self-head key, mainly help breadth80 (6480 -> about 160 matches) and the 888 index.unavailable calls. Re-measure index.unavailable and summon.matches after givenfacts lands, then decide.
- **probereuse**: A refinement of `solver`. With solver1, the stdlib's 338 probes disappear, so what remains is a few ms on ovl and ovr. The components follow-up has no workload that benefits. Not worth the medium risk now.
- **knuthtable**: SEMANTIC CHANGE, effort L and risk high. On the stdlib the speed gain is about 0%. It is a semantics project (removing the depth cap), not part of this slate.
- **hcap**: Sound, but it only helps the synthetic chain9/chain12 programs, which are rejected by the depth cap anyway, and 0% on the stdlib. Deferred.
- **membermemo relaxed mode**: Its validity argument under a non-empty stack, with the implicit/extension-only stack conditions, is not convincing enough to gate: readers with other in-progress declarations could make a baseline recomputation take different paths. Keep strict mode only. Revisit after cyclecut, or once verify mode has run across the corpus.

## Redundancy hypotheses

Testable with the leave-one-out/factorial matrix (counters plus semtest), using the frozen binary of the new build. ALWAYS set HYLO_TC_ABSDEPTH=2, or land the default change first.
H1 (loopcheck redundant): with absmodel on, removing loopcheck changes no counter and no dump on any workload or corpus test (already observed: loopcheck.pruned=0 everywhere). loopcheck is unsound on lc04-07 and lc12 → drop it from the recommended set.
H2 (solver replaced by solver1): solver1 gives counters identical to the baseline on the stdlib and breadth80 (probes≈0, refreshScans≈63) and identical to `solver` on ovl-8-8 and ovr-3-10 (probes/commits, matches 112/20). overload-priority.hylo is dump-identical under solver1 → `solver` becomes unnecessary.
H3 (names replaced by memberskip): with memberskip on, adding names changes neither the summon/applies counters nor the dump on the corpus. memberskip.skipped reaches ≥90% of names.skippedExtensions on the stdlib and members-big, and the review programs n01-n17 match the baseline only under memberskip → retire `names`.
H4 (index partly redundant with givenfacts): with givenfacts on, removing index brings back only the summon-side fan-out (summon.matches 3541 -> about 11180 on the stdlib) and NO canDeriveCoercions cost: canDeriveCoercion calls stay about the same as with index on. Index's coercionSources becomes unnecessary; its summon bucket is still needed (and dtree would supersede it).
H5 (absmodel vs index): complementary, unchanged by this slate. index alone fails div-grow-20 (210 subgoals vs 21); absmodel alone fails breadth80/chain (matches 517680 vs 6480). absfast changes no absmodel.* refutation counter.
H6 (unify vs typevec): unify changes no counter, so its value is constant-factor only. Hypothesis: once typevec's tag-first cast and alias-probe skip land, unify's remaining gain (sequential cast chain in unifiableSameShape) falls below about 1%. Test with timing of {typevec} vs {typevec, unify} over 5 interleaved rounds, plus a new counter unify.castsAvoided. If the difference is within noise, unify can be folded into typevec or dropped.
H7 (membermemo vs memberskip/nocopy): with nocopy, givenfacts and memberskip on, membermemo's stdlib gain falls below 3%. Measure membermemo.hit and timing; if it is under 3%, keep membermemo off by default.
H8 (absmodel's stdlib share): with givenfacts and index on, absmodel.refuted on the stdlib stays about 104 (it is not subsumed), but its time share is under 1% after absfast. absmodel stays justified by div-grow alone.
